# Соль

Соль — веб-сервис персонального подбора заведений на день по временным слотам. Пользователь описывает в чате местоположение, кухню, бюджет и время. Сервис уточняет недостающие параметры, находит заведения и составляет отдельные подборки для завтрака, обеда и ужина.

Сначала места проходят жёсткие фильтры: радиус, работа в течение всего слота, кухня и бюджет. Затем получают оценку до 100 баллов за соответствие поиску, сайт и меню, комфортную загруженность и мероприятия. Карточки показывают расшифровку оценки и ссылки на источники. Карта отображает метки выбранного слота без построения маршрута. Диалоги и найденные места сохраняются в аккаунте.

## Поиск без API Яндекса

По умолчанию приложение работает без ключей Яндекса:

- Gemini использует встроенный инструмент Google Search для поиска реальных заведений, меню, часов работы и датированных мероприятий.
- Второй запрос Gemini извлекает структурированные данные из найденных цитируемых фрагментов. Сервер отбрасывает неподтверждённые поля и записи.
- Photon определяет координаты по найденным адресам; координаты, придуманные моделью, не используются.
- Leaflet показывает интерактивную карту OpenStreetMap.

Для Google Search используется тот же ключ Gemini. Доступность инструмента, тариф и квоты определяются вашим проектом Google AI Studio; отдельного ключа Google Maps не требуется. Веб-поиск не гарантирует актуальность цен и наличие свободного столика. Отсутствующая загрузка получает нейтральное значение `L = 0.5`. Неизвестные часы, кухня или чек не подменяются значениями, подходящими под фильтры.

## Запуск полного приложения

Нужны Docker Engine, Docker Compose v2 и доступный с сервера Gemini API. Для скрипта настройки нужен Node.js 20 или новее. Rust, Elixir и PostgreSQL локально устанавливать не требуется.

Все команды выполняются из корня репозитория.

Если `docker compose version` не работает, установите официальный standalone Compose локально в проект:

```bash
bash scripts/install-compose.sh
```

Скрипт проверяет SHA-256 и сохраняет бинарник в `infra/bin/docker-compose`, без изменения системных каталогов. `scripts/compose.sh` автоматически выбирает плагин Docker, установленный standalone v2 или локальный бинарник. В этом окружении локальный Compose уже установлен.

Создайте конфигурацию:

```bash
node scripts/setup-gastro.mjs
```

Скрипт создаёт `infra/.env` из `infra/.env.example`, генерирует постоянную пару Ed25519 для авторизации, pepper и пароль PostgreSQL. Существующие значения сохраняются; секреты исключены из Git.

В `infra/.env` настройте:

| Переменная                   | Назначение                                                                 |
| ---------------------------- | -------------------------------------------------------------------------- |
| `GEMINI_API_KEY`             | Ключ Gemini, имеющий доступ к выбранной модели и Google Search             |
| `GEMINI_MODEL`               | Модель; по умолчанию `gemini-3.8-flash`                                    |
| `GEMINI_API_MODE`            | По умолчанию `interactions`; `generate_content` оставлен для совместимости |
| `PLACES_PROVIDER`            | `gemini` для поиска через Google; ключ Яндекса не нужен                    |
| `VITE_MAP_PROVIDER`          | `osm` для карты OpenStreetMap без ключа                                    |
| `GEOCODER_URL`               | По умолчанию публичный Photon: `https://photon.komoot.io/api/`             |
| `ALLOWED_ORIGINS`            | Адрес интерфейса; по умолчанию `http://localhost:8088`                     |
| `SMTP_USER`, `SMTP_PASSWORD` | Необязательные параметры существующего сервиса уведомлений                 |

Переменные `YANDEX_SEARCH_KEY`, `YANDEX_GEOCODER_KEY` и `VITE_YANDEX_MAPS_KEY` можно оставить пустыми. Серверный ключ Gemini не попадает в браузер.

Соберите и запустите стек:

```bash
bash scripts/compose.sh app up --build -d
```

Откройте [http://localhost:8088](http://localhost:8088). Зарегистрируйтесь и подтвердите email либо войдите в существующий аккаунт.

При настроенном SMTP сервер выбирается по аккаунту отправителя: Gmail может отправлять письма получателям на других доменах.

Без SMTP сервис уведомлений выводит код в свои логи. Для локальной проверки используйте адрес Gmail или Яндекса и посмотрите код:

```bash
bash scripts/compose.sh app logs --tail=100 notif
```

Пример сообщения в чате: «Завтра хочу японскую кухню в центре Москвы с 13:00 до 15:00, чек до 1500 рублей на человека, без программы».

## Если Gmail SMTP зависает в Docker

В этом окружении Gmail по IPv4 не отдаёт SMTP-приветствие, а по IPv6 TLS и авторизация работают. У Docker bridge нет IPv6-маршрута. Для Linux включён локальный обход в `infra/.env`:

```dotenv
SMTP_HOST_NETWORK=true
SMTP_NETWORK=tcp6
SMTP_TIMEOUT=20s
SMTP_NATS_HOST_PORT=14222
```

`scripts/compose.sh app` автоматически подключает `infra/docker-compose.smtp-host.yml`. Только `notif` использует сеть хоста; NATS опубликован на `127.0.0.1:14222` и не открыт наружу. На серверах с рабочим обычным маршрутом оставьте `SMTP_HOST_NETWORK=false` и `SMTP_NETWORK=tcp`.

Применить настройки и проверить TLS/авторизацию без отправки письма:

```bash
bash scripts/compose.sh app up --build -d notif
bash scripts/compose.sh app exec -T notif ./notif --check-smtp
```

Проверка не отправляет письмо и не выводит пароль. SMTP-соединение имеет ограничение времени; ошибки указывают этап: соединение, приветствие, TLS, авторизация или принятие письма. Успех означает принятие сообщения SMTP-сервером, а не гарантию попадания во входящие. Закрытие соединения после успешного принятия сообщения не считается ошибкой отправки.

## Если письма не отправляются на Mac

При ошибке `dial tcp6 ... no such host` сначала уберите перенесённое с Linux принудительное использование IPv6. В `infra/.env` на Mac:

```dotenv
SMTP_HOST_NETWORK=false
SMTP_NETWORK=tcp4
SMTP_TIMEOUT=20s
SMTP_SECURITY=starttls
SMTP_PORT=587
```

Примените переменные пересозданием контейнера, затем проверьте TLS и авторизацию без отправки письма:

```bash
bash scripts/compose.sh app up -d --no-deps --force-recreate notif
bash scripts/compose.sh app exec -T notif ./notif --check-smtp
```

Обычный `restart` не обновляет переменные контейнера. Если получаете `SMTP greeting`/`connect` с таймаутом, это сетевой сбой до проверки пароля; проверьте доступ из Docker Desktop, VPN и firewall. Если `SMTP authentication` возвращает 535, проверьте Gmail-адрес отправителя и пароль приложения без пробелов.

В обновлённом коде также поддержан Gmail с немедленным TLS на 465. Если порт 587 недоступен, после обновления исходников и пересборки notif можно отдельно проверить другой порт без изменения настроек и отправки письма:

```bash
bash scripts/compose.sh app up --build -d --no-deps notif
bash scripts/compose.sh app exec -T -e SMTP_PORT=465 -e SMTP_SECURITY=tls notif ./notif --check-smtp
```

При успешной проверке сохраните `SMTP_PORT=465` и `SMTP_SECURITY=tls` в `infra/.env` и пересоздайте notif. Оба режима требуют проверенный TLS, шифрование и проверка сертификата не отключаются. При `no such host` даже с `tcp4` проверяйте DNS Docker Desktop; [официальные настройки сети и DNS](https://docs.docker.com/desktop/features/networking/).

## Если сборка gateway зависает на установке Hex

Ошибка `mix local.hex` при загрузке `builds.hex.pm/installs/hex.csv` означает сетевой таймаут установщика. Dockerfile gateway скачивает закреплённые исходники Hex 2.6.0 и Rebar 3.25.1 с официального GitHub: загрузка выполняется через curl с повторами и проверкой SHA-512, а успешные загрузки сохраняются в кеше BuildKit. Hex компилируется внутри образа тем же Elixir/OTP, что и gateway, чтобы избежать несовместимости готовых BEAM-архивов с обновлениями OTP. Для зависимостей установлен таймаут 180 секунд и параллелизм 2, предусмотрены повторные попытки.

После обновления исходников пересоберите только gateway:

```bash
bash scripts/compose.sh app build gateway
bash scripts/compose.sh app up -d --no-deps gateway
```

Если используете Docker Compose напрямую:

```bash
docker compose --env-file infra/.env -f infra/docker-compose.gastro.yml build gateway
docker compose --env-file infra/.env -f infra/docker-compose.gastro.yml up -d --no-deps gateway
```

При первой сборке нужен доступ к `repo.hex.pm` и GitHub. TLS-проверка и контрольные суммы включены. Для доверенного зеркала того же архива можно передать `--build-arg HEX_SOURCE_URL=...` или `--build-arg REBAR3_ARCHIVE_URL=...`; контрольная сумма остаётся обязательной. На macOS используйте обычные `SMTP_HOST_NETWORK=false` и `SMTP_NETWORK=tcp`; отдельный SMTP-обход через host network выше предназначен для нашего Linux-окружения.

## Диагностика 502 и 504 в engine

Строка `tower_http::trace::on_failure` показывает HTTP-статус и общее время запроса. Она сама по себе не указывает, отказали Auth, Gemini или Photon. В обновлённом ядре дополнительно логируются `provider`, `operation`, признаки DNS/таймаута и статус провайдера. API-ключи, токены и тексты диалога не выводятся.

После обновления исходников пересоберите только ядро и запустите проверку:

```bash
bash scripts/compose.sh app up --build -d --no-deps engine
bash scripts/compose.sh app exec -T engine gastro-engine --check-upstreams
```

Проверка обращается к Auth, Gemini и Photon тем же HTTP-клиентом, что и приложение. В Gemini ключ не передаётся: HTTP 400/401/403/429 означает, что HTTP-ответ получен, и не подтверждает доступ к модели или квоту. Генерация не запускается. Диагностика также не требует подключения ядра к PostgreSQL.

Если DNS в контейнере работает, но запрос заканчивается по времени, проверяйте доступ HTTPS из Docker Desktop, VPN, прокси и фильтрацию сети. Таймауты Gemini составляют 40 секунд для разбора/извлечения и 70 секунд для Google Search; Photon — 8 секунд. В обновлённом API таймаут возвращает 504, ошибка DNS и некорректный ответ — 502 с названием провайдера.

Для ошибки DNS `server misbehaving` у engine или notif есть отдельная конфигурация. В `infra/.env` можно включить доступные в вашей сети DNS-серверы:

```dotenv
APP_CUSTOM_DNS=true
APP_DNS_PRIMARY=1.1.1.1
APP_DNS_SECONDARY=8.8.8.8
```

Обёртка автоматически подключит `infra/docker-compose.dns.yml` только для engine и notif. Пересоздайте их:

```bash
bash scripts/compose.sh app up -d --no-deps --force-recreate engine notif
```

При VPN или корпоративной сети укажите разрешённые вашей сетью резолверы; публичные DNS тоже могут быть недоступны. Это настройка по запросу, по умолчанию используется DNS Docker. Внутренние имена сервисов Docker сохраняются. Не заменяйте smtp.gmail.com или API-домены постоянными IP-адресами: адреса меняются, проверка TLS выполняется по имени.

## Если Gemini не отвечает

Ошибки провайдера отображаются в чате с причиной:

- `429 RESOURCE_EXHAUSTED`: исчерпана квота или превышен лимит. Проверьте квоты и биллинг в Google AI Studio.
- `User location is not supported for the API use`: запросы выполняются из неподдерживаемого региона. Нужен разрешённый провайдером доступ с сервера в поддерживаемом регионе.
- Модель недоступна: обновите `GEMINI_MODEL`. Ранее использовавшаяся `gemini-2.5-flash` уже может быть недоступна для новых аккаунтов.
- Не хватает прав или ключ отклонён: проверьте `GEMINI_API_KEY` и разрешения проекта.

Наличие ключа само по себе не гарантирует доступ: должны быть доступны регион, модель, квоты и инструмент Google Search. При сбое приложение не выдаёт демонстрационные заведения за результаты реального поиска. После изменения серверных параметров повторите команду запуска. Для изменения поставщика карт или тайлов требуется пересборка frontend.

## Автономная презентация

Готовый план без регистрации, API-ключей и серверных сервисов:

```bash
bash scripts/compose.sh presentation up --build -d
```

Откройте [http://localhost:8090](http://localhost:8090). Для регистрации используйте [основное приложение на порту 8088](http://localhost:8088): презентация не содержит API авторизации и показывает ссылку «Вход и регистрация». При другом адресе основного приложения задайте `VITE_APPLICATION_URL` перед сборкой презентации. Сразу доступны завтрак, обед и джазовый ужин, карточки, меню, скоринг, схема с метками и смена темы. Кнопки показывают альтернативный обед и пример пустой выдачи с ослаблением бюджета. Все заведения и показатели вымышлены и помечены в интерфейсе. Новая генерация в этом режиме не выполняется; состояние находится в памяти браузера.

Для первоначальной сборки нужна сеть. После сборки презентация не обращается к внешним API или картам. Полный и презентационный стеки используют разные порты и могут работать одновременно.

Без Docker, при наличии Node.js 22.12 или новее и npm:

```bash
cd frontend
npm ci
npm run demo
```

Откройте адрес Vite, обычно [http://localhost:5173](http://localhost:5173). В обычном приложении готовый пример доступен по кнопке «Открыть готовый пример без входа» или через `/?demo=1`.

## Управление сервисами

```bash
# Состояние полного стека
bash scripts/compose.sh app ps

# Логи приложения
bash scripts/compose.sh app logs -f engine gateway frontend

# Пересборка после изменений
bash scripts/compose.sh app up --build -d

# Остановка с сохранением данных
bash scripts/compose.sh app down

# Остановка презентации
bash scripts/compose.sh presentation down
```

Конфигурации находятся в `infra/docker-compose.gastro.yml` и `infra/docker-compose.presentation.yml`. Прежние `docker-compose.dev.yml` и `docker-compose.server.yml` для этих сценариев не используются. Скрипт полного стека передаёт `--env-file infra/.env`, презентации env-файл не нужен. Ошибка `unknown flag: --env-file` со справкой самого Docker обычно означает отсутствие плагина Compose; используйте локальный установщик и обёртку выше.

PostgreSQL, Redis и NATS сохраняют данные в Docker volumes. Смена пароля в env не меняет пароль существующей базы. По умолчанию интерфейсы доступны только на loopback. Для публичного размещения настройте HTTPS и фактический домен в `ALLOWED_ORIGINS`.

## Ограничения бесплатных геосервисов

Публичный Photon рассчитан на умеренное использование и не гарантирует доступность. Ядро кеширует геокодирование до суток, ограничивает кеш 2048 записями и последовательно отправляет не более одного запроса примерно в секунду на процесс. В одном плане обрабатывается не более 12 найденных записей. При росте нагрузки или нескольких репликах engine используйте собственный Photon либо другого совместимого поставщика через `GEOCODER_URL`.

Тайлы OpenStreetMap загружаются браузером по мере просмотра с видимой атрибуцией; массовая загрузка и офлайн-предзагрузка не выполняются. Другой поставщик тайлов задаётся через `VITE_MAP_TILES_URL`. Правила: [Photon](https://github.com/komoot/photon#demo-server), [OpenStreetMap tiles](https://operations.osmfoundation.org/policies/tiles/).

## Проверки

```bash
cargo test --locked --manifest-path services/engine/Cargo.toml
cargo clippy --locked --manifest-path services/engine/Cargo.toml --all-targets -- -D warnings

cd services/gateway
mix deps.get
mix test

cd ../../frontend
npm ci
npm test
npm run build
```

Для Rust локально нужна системная libpq. Dockerfile ядра запускает тесты при сборке.

Проверка полного запущенного стека без отправки реальных писем:

```bash
python3 scripts/check-gastro.py
```

Тест требует пустых SMTP-параметров, создаёт два временных аккаунта, проверяет подтверждение email через заглушку, JWT, изоляцию истории и скоринг, затем удаляет только свои записи. Для одного реального сообщения через настроенный Gemini добавьте `--include-gemini`; ошибки квоты и региона будут показаны отдельно от результата локальных проверок.

Подробности: [архитектура и контракты](docs/architecture.md), [пример запроса ранжирования](docs/rank-request.json).
